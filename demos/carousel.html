Coverflow Floofs

A scroll container that snaps one slide at a time, with the scrollbar hidden so it swipes like an app. Whichever slide is snapped flattens and comes forward; the browser draws the dots and arrows.

Progressive enhancement, live

What this browser is giving you right now. Every tick is decided by @supports, not JavaScript. Swiping and snapping work everywhere; the tilt, the dots and the arrows are the newest CSS on the site, so where they are missing you get a flat swipe carousel.

CSS · graded live by @supports

  • scroll-snap-type every slide settles centred, one per swipe
  • scrollbar-width: none swipe, don't scroll-bar
  • scroll-initial-target start on the third floof, not the first
  • @container scroll-state(snapped) the snapped slide flattens and comes forward
  • animation-timeline: view() which side of centre a slide is on
  • ::scroll-marker the dots, drawn by the browser
  • ::scroll-button() the arrows, drawn by the browser
  • linear() springy easing on the tilt

Full disclosure: the tilt, dots and arrows are Chrome only for now, and typed custom properties via @property are what let the tilt transition at all. Everywhere else this is a flat carousel that still swipes, snaps and scrolls with the keyboard. There is an alternative method that you can use for this (see the archive folder) using :has(), which worked in every browser, but could not swipe. Because it is an expected behaviour that essentially made the slider unusable on mobile, swipe won. One thing that the other method gives you though is infinite scroll - which if you are doing an automated carousel (that doesn't need swipe) is still pretty neat!
