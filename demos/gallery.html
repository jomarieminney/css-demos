Progressive enhancement, live

What this browser is giving you right now. Every tick is decided by @supports, not JavaScript. Filtering and sorting only need :has(). The fade that hides the shuffle is a plain animation that works everywhere; it is how it gets replayed on every click that is the trick.

CSS · graded live by @supports

  • :has(#show-cat:checked) the page knows which button is on
  • [data-species~="cat"] one word from a list, so Fia can be two things
  • animation-name a new name replays the fade on every click
  • grid-template-rows: subgrid ratings and tags line up across a row
  • order: calc(var(--rating) * -1) sort by the number the bar draws
  • counter() hidden cards don't count, so the total is live

Full disclosure: two things here that I would actually use JavaScript to improve.

  • The cards don't glide to their new places: the gallery blinks out and fades back in to hide the jump. Actually moving them needs document.startViewTransition().
  • order only moves cards on screen: a screen reader still meets them in the order they are in the markup. That's fine for a gallery of photos, but think twice before sorting a table this way.
