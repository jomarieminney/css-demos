Progressive enhancement, live

What this browser is giving you right now. Every tick is decided by @supports, not JavaScript. The strip itself is one @keyframes rule that has worked everywhere for a decade; the newer parts are how it behaves when you reach for it.

CSS · graded live by @supports

  • animation-play-state hover or focus holds it still
  • mask-image the ends fade into the page
  • :has(:focus-visible) a keyboard visit stops it and shows every logo
  • prefers-reduced-motion one still row instead
  • @starting-style the dialog fades and lifts in

HTML · CSS can't grade these, so check Can I use

  • inert the copy can't be focused or clicked
  • command / commandfor each logo opens a dialog
  • <dialog> modal with focus trap and Escape

Full disclosure: the logos really are in the page twice, because CSS can't clone an element. The copy is aria-hidden and inert, so it is scenery. Each copy also has to be at least as wide as the strip, or a gap shows before the loop comes round; with six logos that's never a problem, but with two you would repeat them in the markup.
