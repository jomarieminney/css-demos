Progressive enhancement, live

What this browser is giving you right now. Every tick is decided by @supports, not JavaScript. Narrow the window and the strip falls back to a stack. Technique after Pure CSS Tabs Using Details, Grid, and Subgrid on CSS-Tricks.

CSS · graded live by @supports

  • subgrid every tab shares one row of tracks
  • ::details-content the panel is a grid item
  • :has() quantity query counts the tabs
  • @starting-style tabs and panel enter on load
  • background-clip: text gradient names
  • linear() springy easing
  • @layer cascade order · no layers, no styles at all

HTML · CSS can't grade these, so check Can I use

  • <details name="…"> one open at a time
  • <details> + <summary> the disclosure itself

Full disclosure: these are six summary elements in a row, not an ARIA tablist. Screen readers announce them as disclosures, and there is no arrow-key navigation between tabs (it's still keyboard accessible - you just need to use tab instead of arrow keys). The open tab ignores mouse clicks so it can't be closed, but Enter or Space on it still can, because CSS can't veto a keypress. This example is mainly showing off how subgrid works, and a genuine tablist is probably a good argument for a few lines of lightweight JavaScript in order to provide a better user experience for assistive tech.
